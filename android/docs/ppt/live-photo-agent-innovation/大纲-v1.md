# Live Photo Agent 全项目技术路线 PPT · 大纲 v3（高密度技术评审）

## 基本设定

- 场景：项目技术评审
- 时长：15 分钟；计划讲述 13.2 分钟，预留 1.8 分钟
- 风格：瑞士国际主义（Style B）+ 克莱因蓝 IKB
- 主线：从网页端云模型原型，到 vivo 手机端独立闭环，再扩展到语言驱动的内容级编辑
- 密度参考：`/home/jiangrui/PolyCamera/demo/tsinghua-ppt/`
- 叙事原则：每页同时展示“协议/机制—故障证据—根因—修复—验收—边界”，不把后期 SD 生成替换等同于整个项目

## 页面密度合同

- 标题必须直接陈述本页技术结论，不使用“系统架构”“实验结果”式空标题。
- 正文页至少包含两类证据：运行参数、机制图、故障日志、对照表、真实图像或验收数字。
- 每个重要数字注明口径；远程 AI Hub、host oracle、vivo 真机和 Android App 闭环不得混写。
- 每页底部保留来源与能力边界；失败与未完成项必须和成功结果同时展示。

- Web/云端阶段证明的是交互、规划合同、工具执行和媒体处理可行，不等于端侧部署完成。
- `102/102` 是 VLM 索引全量运行结果；`31/31` 是注册 executor 真机逐项验收；`30/30` 是动态绑定验收。
- `N=339` 是跟踪与确定性局部效果证据，不是视频扩散。
- SD2 当前只生成一个锚帧并做短刚性传播；生成制品永久 `publishEligible=false`。
