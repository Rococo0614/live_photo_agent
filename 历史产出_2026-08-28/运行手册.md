# 小红书 Live Photo 玩法洞察 —— 全自动流水线

把 `01_live玩法洞察/脚本/` 下 16 个脚本串成一条**可定时重复运行**的全自动链路：
**自动搜索发现 → 抓取 → 云端分析 → 双通道卡片 → 生成 HTML**。

## 数据流

```
【P1 发现】              【P2 抓取】          【P3 分析】            【P4 卡片】             【P5 可视化】
search_xhs.py     ┐
quick_find.py     ├→ URL ─→ fetch_xhs.py ─→ note.json ─┬→ observe_batch.py(云端qwen) ─→ 观察报告md ─┐
fetch_and_search.py┘            +lives/*.mp4           │→ vision_batch.py(本地Ollama)                ├→ gen_card_generic.py → 交付/*.html
                              +covers/*.jpg           └→ gen_card_dual.py(A云端+B本地) ─→ A/B卡片+对比┘
                              +frames/
```

统一接口是 `数据/xhs_notes/<note_id>/note.json`，下游脚本全部兼容。

## 一键运行

```bash

# 只跑到某个阶段
```

## 编排器设计要点

- **幂等**：已抓取过的 `note_id` 自动跳过，不重复烧账号/额度（状态存 `运行记录/state.json`）
- **URL 收集 + 去重投票**：所有发现的帖子 URL 记入 `运行记录/urls.json`（note_id → 首次/最近出现时间、票数、状态）。同一帖子再次被遇到（每天自动搜索都会返回当前收藏最高的热帖）→ **votes +1 并跳过重复抓取/分析**。新帖首次抓取算 1 票。
- **容错**：单阶段失败不中断整条链，出日志；**本地 Ollama 不在时自动降级为纯云端**
- **日志**：每次运行写 `运行记录/<日期>.log`
- **通用 HTML**：`gen_card_generic.py` 从 `note.json` 动态读标题/互动/Live，替代原硬编码的 `gen_card.py`（莫兰迪规范见 `playbook-card-viz` skill）

## 2026-08-13 实测发现并修复（第二轮：创意玩法教程方向）

**产品决策**：洞察目标从「Live 图素材」改为「Live 图的创意玩法教程」。两类教程都收：① 帖子本身含 Live 视频的教程帖；② 视频/图文教程帖（教怎么做创意效果，本身无 Live）。

- **搜索关键词改向**：`fetch_and_search.py` `KEYWORD` 从 `live实况图 氛围感`（素材方向）改为 `live图 创意玩法教程`；`quick_find.py` 关键词改为 `live图 创意玩法教程 / live图 创意玩法 / 实况照片 创意教程`。
- **`fetch_and_search.py` 契约 bug**：一体式脚本抓取后不输出 `FETCH_URL=`，编排器解析不到就退回 quick_find 白跑一遍。已补 `FETCH_URL=` + `FRESH_NOTE_ID=` 输出；`run_pipeline.py` 新增 `extract_fresh_note_id()` 解析，一体式新抓直接视为新帖（不误判「已抓取过」）。
- **重复热帖保护**：一体式重抓但 `state` 里已 `analyzed_at` 的帖 → 仅投票不重分析（避免每天重复烧 DASHSCOPE 额度）。
- **视频教程帖支持**：`fetch_xhs.py` 对 `type=video` 帖从 `nd.video.media.stream` 提取视频 URL，下载为 `video_XX.mp4` 并抽帧（之前只下封面）；`run_pipeline.py` `has_live()` 放宽为 `has_media()`（Live 或视频）；`gen_card_dual.py`/`gen_card_generic.py` 的可分析媒体过滤同步放宽。
- **GBK 编码崩溃（第三/四起）**：`observe_video.py`（打印含 emoji 文件名）、`gen_card_generic.py`（打印含 emoji HTML 文件名）均缺防护，已加 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。
- **`gen_card_dual.py` meta 解析 bug（隐藏）**：`json.load(open(note_json))` 在 Windows 默认 GBK 打开 UTF-8 文件抛 UnicodeDecodeError 被吞 → meta 为空 → **A/B 卡片的 note_title/note_tags 一直是空的**。已改为 `encoding="utf-8"` 显式读取 + 正确取 `data["meta"]`。验证：视频教程帖卡片 title 正确填充。

## 2026-08-13 实测发现并修复

- **`fetch_xhs.py` + `run_pipeline.py` GBK 编码崩溃（连锁）**：帖子标题含 emoji（如「…😋😋」）时 `fetch_xhs.py` 打印标题抛 UnicodeEncodeError → 抓取失败且 note.json 未写入；编排器打印子进程输出（含替换字符 `�`）时同样崩在 GBK 上，连失败日志都没写。两个脚本均已加 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（与 `gen_card_dual.py` 同款防护）。
- **2026-08-13 全流程回归通过**：P1 自动发现（fetch_and_search 未命中→quick_find 命中）→ P2 抓取 → P3 云端观察（45s/2143 字）→ P4 双通道卡片（Ollama 不在自动降级纯云端 + B 占位）→ P5 通用 HTML，全链路正常。

## 2026-08-11 实测发现并修复

- **`gen_card_dual.py` emoji 崩溃**：Windows GBK 控制台打印 `🌐` 抛 UnicodeEncodeError，导致 P4 在调用云端前崩溃。已加 `sys.stdout.reconfigure(encoding="utf-8")`（`compare_cloud_vs_local.py` 同修）。
- **`gen_card_dual.py` 本地降级**：原逻辑「云端+本地都成功才写文件」，本地 Ollama 不在时整体崩溃，A 卡片也不落盘。已改为容错：云端 A 卡片独立写入，本地 B 通道失败降级为占位卡片 + 对比摘要标注失败。
- **编排器无 Live 保护**：`quick_find`/`fetch_and_search` 选出的「最佳帖」可能没有 Live（只有封面）。已加 `has_live()` 检查，新抓取的帖无 Live 则记录 `skipped=no_live` 并跳过下游，不污染分析/卡片。
- **自动搜索 7 天窗口**：搜索返回的候选大多超过 7 天（最近也 48 天前），`days<=7` 过滤后常无目标 → 每天自动跑可能空转（收集 URL + 投票后结束）。**已确认保持现状**：宁缺毋滥，新帖靠手动提供 URL 或等 7 天内新帖出现。
